# 허브 화면(샘플)

플랫폼팀이 브라우저에서 허브의 지금 상태를 보고, 운영 명령을 버튼으로 누르는 샘플 화면입니다. 이 PC에서만 열리고, 로그인이 없고, 어디에도 올리지 않습니다. 화면의 값은 모두 그 순간 AWS에서 읽은 것이고, 미리 채운 값은 없습니다. 운영용 화면이 아니라 허브가 하는 일을 보여 주는 샘플이고, Terraform 모듈은 없습니다.

## 실행하는 법

```
make ui                                   # http://127.0.0.1:8300 , Ctrl+C로 멈춥니다
```

| 환경 변수 | 뜻 | 기본값 |
|---|---|---|
| `HUB_UI_PORT` | 포트. 주소는 언제나 `127.0.0.1`입니다 | 8300 |
| `HUB_UI_LANG` | 화면의 언어, `ko` 또는 `en` | `ko` |
| `HUB_UI_TZ` | 화면의 시각을 보이는 시간대 | `Asia/Seoul` |

- 리전과 접두어는 `make`의 규칙으로 `.env`에서 읽습니다([시작하기의 `.env`](../../docs/getting-started.md#env)). `python -m platform_team.hub_ui`로 직접 실행하면 `.env`를 읽지 않고 셸의 `AWS_REGION`, `DEMO_PREFIX`를 씁니다.
- 모든 읽기와 버튼은 실행한 셸의 자격 증명으로 돕니다. 그 자격 증명이 할 수 있는 것은 화면도 할 수 있습니다.
- 화면은 5초마다 자기를 다시 그립니다. 폼에 포커스나 쓰던 글이 있으면 다시 그리지 않습니다.
- 허브가 올라와 있지 않으면 "이 계정과 리전에 허브가 배포되어 있지 않습니다"를 보입니다. 허브를 지우고 다시 올렸으면 화면은 옛 값을 쥐고 있으므로 화면도 다시 실행합니다.

## 구조

```
브라우저  http://127.0.0.1:8300
  │
  ▼
허브 화면 (FastAPI, python -m platform_team.hub_ui, 셸의 자격 증명으로 돕니다)
  │
  ├─ 안전 검사 (safety.py): 통과하지 못하면 403이고, AWS를 부르지 않습니다
  │
  ├─ 읽기 (GET)
  │    패널마다 따로 AWS를 읽습니다 (하나가 실패해도 나머지는 보입니다)
  │    읽은 값은 5초 동안 다시 쓰고, 화면은 5초마다 다시 그립니다
  │
  └─ 버튼 (POST): 작업 하나를 스레드에서 돌립니다 (한 번에 하나)
       ├─ 반려: reject_agent (reject.sh와 같은 함수)
       ├─ guard_prompt의 모드: policy_rollout (rollout.sh)
       ├─ 커스텀 가드레일 붙이기와 떼기: guardrail_attach (guardrail.sh)
       ├─ 멈춤과 재개: stop_agent.stop, stop_agent.resume (stop.sh, resume.sh)
       └─ 작업 칸에 그 명령이 출력하는 줄이 그대로 나옵니다
```

## 페이지

```
홈 /  ← 카탈로그와 플랫폼 구성
  ├─ 수: 호스팅된 에이전트, 승인 대기, 승인된 도구
  ├─ 플랫폼 구성: 게이트웨이 둘, policy engine, 카탈로그, 상태 머신, 알림 주제
  └─ 경보, 카탈로그의 레코드, 마지막 작업

호스팅 심사 /reviews  ← 호스팅 심사
  ├─ 에이전트마다 카드: 최근 심사의 일곱 단계 띠, 실패한 단계와 오류
  ├─ Scan에서 떨어졌으면 취약한 패키지의 줄
  └─ 버튼: 반려하기

전사 정책 /policies  ← 전사 정책, 커스텀 가드레일
  ├─ 두 게이트웨이의 정책과 모드, guard_prompt의 지난 60분 기록 모드 집계
  └─ 버튼: 기록 모드로 걸기, 적용 모드로 올리기, 끄기, 가드레일 붙이기, 떼기

에이전트 /agents  ← 모니터링, 멈추기와 재개
  ├─ 도구 호출 경보 상태와 최근 15분의 1분 합계 막대
  ├─ 에이전트마다 지난 60분의 호출, 세션, 오류, CPU, 메모리, 멈춤 상태
  └─ 버튼: 멈추기, 재개 (harness 에이전트는 버튼 대신 멈출 수 없는 이유)
```

| 페이지 | 보이는 것 | 버튼 | 읽는 곳 |
|---|---|---|---|
| 홈 | 호스팅된 에이전트, 승인 대기 중인 에이전트, 승인된 도구의 수. 두 흐름의 개념도. 게이트웨이 둘, 정책 엔진, 카탈로그, 심사의 상태 머신, 알림 토픽의 상태. 전사 정책 `guard_prompt`의 모드와 커스텀 가드레일이 붙어 있는지. 경보, 카탈로그의 레코드, 마지막 작업 | 없음 | AWS Agent Registry `ListRegistryRecords`, `GetGateway`, `GetPolicyEngine`, `GetRegistry`, `DescribeStateMachine`, SNS `GetTopicAttributes`, SSM, CloudWatch `DescribeAlarms` |
| 호스팅 심사(`/reviews`) | 에이전트 신청마다 카드 하나. 가장 최근 심사의 상태와 일곱 단계의 띠, 실패했으면 그 단계와 오류. Scan에서 실패한 심사는 취약점이 있는 패키지의 줄도 보입니다. 카드를 누르면 `/reviews/<에이전트>`에서 단계마다의 시간과 Step Functions 콘솔로 가는 링크를 봅니다 | 반려하기 | `ListRegistryRecords`, `GetRegistryRecord`, Step Functions `ListExecutions`, `DescribeExecution`, `GetExecutionHistory`, CloudWatch Logs `GetLogEvents` |
| 전사 정책(`/policies`) | 두 게이트웨이의 정책과 그 모드. `guard_secret`이 걸린 에이전트의 수. `guard_prompt`의 모드와 최근 60분 동안 기록 모드가 센 요청. 커스텀 가드레일이 붙어 있는지 | 기록 모드로 걸기, 적용 모드로 올리기, 끄기, 커스텀 가드레일 붙이기, 떼기 | SSM, `ListPolicies`, CloudWatch `GetMetricStatistics`, `GetGateway` |
| 에이전트(`/agents`) | 도구 호출 경보의 상태와 최근 15분의 1분 합계 막대. 에이전트마다 최근 60분의 호출, 세션, 오류, vCPU-시간, GB-시간과 멈춤 상태. 도구마다 최근 60분의 호출 수 | 멈추기, 재개 | CloudWatch `DescribeAlarms`, `GetMetricData`, `ListPolicies`, `ListGatewayTargets`, 카탈로그 |

- 패널마다 읽기가 따로 돕니다. 하나가 실패하면 그 자리에만 이유 한 줄이 나오고, 나머지는 그대로 보입니다.
- 읽은 값은 5초 동안 다시 씁니다. 끝난 심사의 실행 기록은 앱을 다시 실행할 때까지 쥐고 있고, 샘플이라 그 양에 한도를 두지 않았습니다.
- 호스팅 심사 페이지는 Step Functions의 실행을 새로운 것부터 50개만 읽습니다.
- Step Functions 콘솔 링크는 브라우저의 AWS 콘솔 로그인으로 열립니다.
- harness 에이전트는 에이전트 게이트웨이에 진입이 없어서, 멈추는 버튼 대신 그 이유를 보입니다.
- Lambda 단계가 실패한 심사의 오류 줄은 AWS에서 보지 못했습니다. 그런 심사가 없었습니다.

## 작업(버튼)

버튼은 셸 명령과 같은 함수를 이 앱 안의 작업으로 돌립니다. 셸 명령은 화면 없이도 그대로 씁니다.

| 하는 일 | 같은 셸 명령 |
|---|---|
| 반려 | `reject.sh` |
| `guard_prompt`의 모드 바꾸기 | `rollout.sh` |
| 커스텀 가드레일 붙이기와 떼기 | `guardrail.sh` |
| 멈춤과 재개 | `stop.sh`, `resume.sh` |

- 작업은 한 번에 하나입니다. 작업이 도는 동안 누른 버튼은 받지 않고, 받지 않았다는 문장을 보입니다.
- 작업 칸에는 그 명령이 출력하는 줄이 나옵니다. 이 줄은 페이지의 언어와 상관없이 영어입니다.
- 반려 사유는 1자에서 255자까지입니다(카탈로그의 `statusReason` 한도). 반려 버튼은 레코드가 `PENDING_APPROVAL`, `REJECTED`, `DRAFT`일 때만 보입니다.
- 같은 레코드의 심사가 돌고 있으면 반려는 아무것도 바꾸지 않고 멈춥니다. `APPROVED` 레코드는 반려하지 못합니다([호스팅 심사](../hosting_review/README.md)).
- 작업은 메모리에만 있어서 앱을 멈추면 사라집니다.
- 작업이 도는 중에 앱을 멈추면 그 함수도 중간에 멈춥니다. 코드가 그렇게 하고, 해 보지는 않았습니다.

## 안전 규칙

로그인이 없는 화면이 AWS를 바꿀 수 있으므로, 앱은 모든 요청에 이 규칙을 지킵니다(`safety.py`). 거부된 요청은 AWS를 부르지 않습니다.

```
요청
  │
  ├─ Host가 127.0.0.1:<포트> 또는 localhost:<포트>인가? 아니면 403 (DNS rebinding 막기)
  │
  ├─ 바꾸는 요청(POST)이면
  │    ├─ Origin이 이 화면인가? 아니면 403 (다른 사이트의 폼 막기)
  │    └─ 숨은 칸 token이 이번 실행의 페이지 토큰인가? 아니면 403
  │
  ├─ 모든 답에 붙이는 헤더
  │    ├─ X-Frame-Options: DENY (다른 사이트가 이 화면을 틀에 넣지 못합니다)
  │    └─ Content-Security-Policy (이 앱의 스크립트만 돕니다)
  │
  └─ 모든 본문의 12자리 계정 ID → <ACCOUNT>
```

- 앱은 `127.0.0.1`에서만 듣고, 요청의 `Host`가 `127.0.0.1:<포트>`나 `localhost:<포트>`가 아니면 403입니다. 다른 사이트가 자기 이름을 `127.0.0.1`로 돌려 놓는 속임수(DNS rebinding)를 이것으로 막습니다.
- 바꾸는 요청은 `Origin`이 이 화면이고 폼의 숨은 칸 `token`에 페이지 토큰이 있어야 받습니다. 토큰은 앱을 실행할 때마다 새로 만들므로, 앱을 다시 실행한 뒤 예전 탭에서 누르면 403이고 페이지를 다시 열면 됩니다.
- 다른 사이트가 이 화면을 틀(frame)에 넣지 못합니다(`X-Frame-Options: DENY`). `Content-Security-Policy`는 이 앱이 쓴 스크립트만 돌게 하고, 이 앱 밖의 스크립트, 스타일, 그림을 가져오지 못하게 합니다.
- 앱이 보내는 모든 본문은 `aws_helpers.mask`를 지나 12자리 계정 ID가 `<ACCOUNT>`로 바뀝니다. 예외는 Step Functions 콘솔로 가는 303의 주소(`Location`)이고, 그 안의 실행 ARN에 계정 ID가 있습니다.
- 레코드의 설명, 시험 호출의 답, 오류처럼 개발자나 에이전트가 정한 글은 템플릿 엔진이 이스케이프합니다.

이 규칙이 막지 못하는 것:

- 다른 사이트가 링크나 그림 주소로 브라우저에게 이 화면의 페이지를 GET하게 하는 것. 그 페이지의 AWS 읽기가 셸의 자격 증명으로 돌지만, 바꾸는 요청은 아니고 그 사이트는 답을 읽지 못합니다.
- 이 PC의 다른 프로그램과 다른 사용자. 페이지에서 토큰을 읽어 버튼을 누를 수 있으므로, 여럿이 쓰는 PC에서는 실행하지 않습니다.
- 브라우저 확장 프로그램처럼 이 화면의 페이지 안에서 도는 코드.
- 앱 앞에 프록시를 두거나 포트를 밖으로 여는 것.
- 자격 증명의 범위. 화면은 실행한 셸의 자격 증명이 허락하는 만큼 할 수 있습니다.
- 통신은 암호화하지 않는 HTTP입니다. 이 PC 안의 통신(loopback)이기 때문입니다.

## 테스트와 확인

단위 테스트(`tests/test_hub_ui_app.py` 등)는 `tests/fakes.py`의 가짜 AWS 클라이언트로 돌고 AWS를 부르지 않습니다.

`make e2e-ui`(`e2e_checks/e2e_hub_ui.py`)는 올라와 있는 허브에서 화면을 확인합니다. 화면을 이 PC의 빈 포트에서 실행하고, 페이지를 읽고 브라우저처럼 버튼을 누르고, 페이지의 값을 boto3로 읽은 값과 맞춰 봅니다. `make e2e-ops`가 끝난 허브에서만 시작합니다. 에이전트 넷이 `APPROVED`이고, `guard_prompt`가 꺼져 있고, 커스텀 가드레일이 떨어져 있고, 멈춘 에이전트와 도는 심사가 없어야 합니다. 아니면 0번 줄에 무엇이 다른지 출력하고 멈춥니다.

확인은 여덟입니다.

1. 모든 페이지가 200이고 `샘플 화면`이 있고 계정 ID가 없습니다.
2. 홈의 수와 경보가 카탈로그와 CloudWatch가 주는 것과 같고, 플랫폼 구성의 여섯 줄이 저마다 상태를 보입니다.
3. `quality_agent`와 `release_review`가 `APPROVED`이고, 가장 최근 심사의 일곱 단계가 모두 통과입니다. 단계마다의 시간이 Step Functions의 실행 기록과 같습니다.
4. `quality_agent`의 취약한 변형을 제출하면 페이지가 Scan에서의 실패와 취약점 줄을 보입니다. 반려 뒤의 레코드 상태가 작업이 출력한 상태와 같고, 고친 버전을 다시 제출하면 `APPROVED`입니다.
5. 기록 모드로 걸면 Runtime 에이전트마다 `LOG_ONLY`이고, 숨은 지시 하나를 페이지의 집계가 셉니다. 적용 모드로 올리면 `ACTIVE`이고, 끄면 정책이 없습니다.
6. 커스텀 가드레일을 붙이면 코드명이 줄바꿈 바로 뒤에 오는 요청이 403입니다. 떼면 떨어져 있다고 읽습니다.
7. `quality_agent`를 멈추면 에이전트 게이트웨이로 부를 때 403이고 `release_review`는 200입니다. 재개하면 다시 200입니다.
8. 작업이 도는 동안 버튼을 다시 누르면 받지 않습니다.

- 바꾼 것은 확인마다 되돌리므로 같은 허브에서 다시 돌릴 수 있습니다.
- 확인이 중간에 멈추면 스크립트가 끝에서 `guard_prompt`, 커스텀 가드레일, 멈춘 에이전트를 리포의 명령(`rollout.sh guard_prompt off`, `guardrail.sh detach`, `resume.sh`)으로 되돌립니다. `quality_agent`의 레코드는 되돌리지 않고, `APPROVED`가 아니면 되돌리는 명령(`dev_team/agent_template/publish.sh dev_team/quality_agent`)을 출력합니다.
- `E2E_UI_HOLD=<초>`를 주면 네 페이지를 그만큼 그대로 둔 뒤에 다음 버튼을 누릅니다. 화면을 보거나 녹화하기 위한 것입니다.
- 기록은 `e2e_checks/last-run-ui.log`에 남습니다.

2026-11-23에 `make e2e-ops`가 끝난 허브(`us-west-2`, 접두어 `hub`)에서 `E2E_UI_HOLD=20`으로 두 번 돌렸고, 두 번 모두 8개 통과했습니다. 약 13~14분(774~851초)이 걸렸고, 기다린 80초씩이 들어 있습니다. 페이지의 첫 읽기는 0.3~3.3초였고, 바로 뒤의 읽기는 0.1초 안이었습니다. 버튼의 작업은 2~62초 걸렸고, 기록 모드의 집계는 숨은 지시를 보내고 35~66초 뒤에 그것을 셌습니다.

화면의 틀은 [ai-governance-hub](https://github.com/gonsoomoon-ml/ai-governance-hub)(MIT-0)에서 가져와 고쳤습니다. 색, 밝은 테마와 어두운 테마, 메뉴, 단계 띠, 폼 스크립트, 글 표, 시각 형식이 그렇고, 리포 루트의 `NOTICE`에 적었습니다.
