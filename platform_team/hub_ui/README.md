# 허브 화면(샘플)

플랫폼팀이 브라우저에서 허브의 지금 상태를 보는 샘플 화면이다. 이 PC에서만 열리고, 로그인이 없고, 어디에도 올리지 않는다. 화면의 모든 값은 그 순간 AWS에서 읽은 것이고(몇 초 동안 다시 쓴다, 아래 "값은 어디서 오나"), 만들어 넣거나 미리 채운 값은 없다. 운영용 화면이 아니라 허브가 하는 일을 보여 주는 샘플이다. Terraform 모듈은 없다.

메뉴에는 네 페이지가 있다: 홈, 흐름 1의 호스팅 심사, 흐름 2의 전사 정책과 에이전트. 지금 있는 것은 홈뿐이고, 나머지 세 페이지는 아직 없어서 "이 화면에는 그런 페이지가 없습니다"라는 페이지(404)를 보인다. 없는 주소는 모두 이 페이지를 받는다. 버튼이 있는 페이지는 셸 명령이 부르는 것과 같은 Python 함수를 부르게 되어 있고, 셸 명령은 화면 없이도 그대로 쓴다.

## 띄우는 법

```
make ui                                   # http://127.0.0.1:8300 , Ctrl+C로 멈춘다
```

- 리전과 접두어는 다른 명령과 같다. `make ui`는 `make`의 규칙으로 `.env`도 읽는다([README의 `.env`](../../README.md#env)). `python -m platform_team.hub_ui`로 직접 띄우면 셸의 `AWS_REGION`, `DEMO_PREFIX`(없으면 `us-west-2`, `hub`)를 쓰고 `.env`는 읽지 않는다.
- 자격 증명은 띄운 셸의 것이다. 화면의 모든 읽기와 버튼이 그 자격 증명으로 돈다. 그 자격 증명이 할 수 있는 것은 화면도 할 수 있다.
- `HUB_UI_PORT`: 포트(기본 8300). 주소는 언제나 `127.0.0.1`이다. 코드에 고정되어 있어 바꾸는 설정이 없다.
- `HUB_UI_LANG`: 고르지 않은 페이지의 언어, `ko`(기본) 또는 `en`. 머리줄의 `한 | EN`으로 바꾸면 쿠키 `hub_lang`에 남는다. 밝게, 어둡게, 자동(OS를 따른다)은 쿠키 `hub_theme`에 남는다.
- `HUB_UI_TZ`: 화면의 시각을 보이는 시간대(기본 `Asia/Seoul`), `MM/DD HH:MM:SS`로 쓴다. 모르는 이름이면 UTC다.
- 허브의 값(SSM `/<prefix>/platform/`)은 그것이 필요한 첫 페이지에서 한 번 읽는다. 값이 없으면 "배포되어 있지 않다"는 페이지를 보이고, 다음 페이지에서 다시 읽는다. 그래서 화면을 띄운 채 `make deploy`를 돌리면 화면이 저절로 홈으로 바뀐다(코드가 그렇게 한다. 해 보지 않았다). 반대로 허브를 지우고 다시 올리면 화면은 옛 값을 쥐고 있으므로 화면을 다시 띄운다.
- 화면은 5초마다 자기를 다시 그린다. 폼의 칸(입력 칸, 글 칸, 고르는 칸)에 포커스가 있거나 글을 쓰는 칸에 글이 있으면 다시 그리지 않는다. 다시 그려도 스크롤 위치는 그대로다. 링크나 버튼에 있던 포커스는 풀린다. 이 앱 밖에서 가져오는 스크립트, 스타일, 글꼴은 없다.

## 홈

| 패널(`id`) | 보이는 것 | 읽는 곳 |
|---|---|---|
| `panel-counts` | 호스팅된 에이전트(AGENT 레코드 가운데 `APPROVED`), 심사 중인 에이전트(`PENDING_APPROVAL`), 승인된 도구(MCP 레코드 가운데 `APPROVED`)의 수 | AWS Agent Registry `ListRegistryRecords` |
| `pictures` | 두 흐름의 개념도(흐름 1. 호스팅, 흐름 2. 운영). 누르면 원본 크기로 연다. 그림은 한국어로만 있다. | 이 폴더의 `static/` |
| `panel-platform` | 에이전트 게이트웨이, 도구 게이트웨이, 정책 엔진, 카탈로그, 호스팅 심사의 상태 머신, 알림 토픽의 이름과 상태, 그리고 그것을 돌리는 AWS 서비스 | `GetGateway`(둘), `GetPolicyEngine`, `GetRegistry`, `DescribeStateMachine`, SNS `GetTopicAttributes`(토픽은 상태가 없어서 확인된 구독의 수를 보인다) |
| `panel-company` | 전사 정책 `guard_prompt`의 모드(기록 모드, 적용 모드, 꺼짐)와 커스텀 가드레일이 에이전트 게이트웨이에 붙어 있는지 | SSM `/<prefix>/policies/`(`rollout.sh`가 적는 값), `GetGateway`와 `ListGatewayTargets`(`guardrail.sh status`와 같은 함수) |
| `panel-alarms` | 이름이 `<prefix>-`로 시작하는 알람과 그 상태 | Amazon CloudWatch `DescribeAlarms` |
| `panel-catalog` | 카탈로그의 레코드(이름, 종류, 상태) | AWS Agent Registry `ListRegistryRecords` |
| `panel-job` | 돌고 있는 작업, 없으면 마지막 작업과 그 작업이 찍은 줄 | 이 앱 |

메뉴의 호스팅 심사 옆 숫자는 심사 중인 에이전트의 수다(`panel-counts`와 같은 읽기). 각 패널의 읽기는 따로 돈다. 하나가 실패하면(예를 들어 권한이 없으면) 그 패널에 이유 한 줄이 나오고 나머지 패널은 그대로 보인다. 읽은 값은 5초 동안 다시 쓰므로 5초 안의 두 페이지는 AWS를 한 번 읽는다. 실패한 읽기는 다시 쓰지 않는다.

## 작업(버튼)

버튼은 셸 명령과 같은 함수를 이 앱 안의 작업(thread)으로 돌린다. 버튼을 누르면 앱은 언제나 페이지로 돌려보내고(303), 그 페이지가 결과의 문장을 보인다. 받은 것은 초록 칸, 받지 않은 것(빠지거나 맞지 않는 값, 모르는 이름)은 빨간 칸이다. 작업은 한 번에 하나다. 작업이 도는 동안 다른 버튼을 누르면 받지 않고, 누른 페이지로 돌아가 "다른 작업이 진행 중"이라는 문장을 보인다. 작업이 도는 동안 페이지는 2초마다 그 작업이 찍은 줄을 다시 그리고, 작업이 끝나면 한 번 새로 읽는다. 앱을 다시 띄워 그 작업이 없어졌을 때도 한 번 새로 읽는다. 작업이 끝나면 다시 쓰던 값을 버리므로 그 뒤의 페이지는 AWS를 새로 읽는다. 실패한 작업은 이유를 한 줄로 보인다(계정 ID는 `<ACCOUNT>`). 작업은 메모리에만 있어서 앱을 멈추면 사라진다. 작업이 도는 중에 앱을 멈추면 그 함수도 중간에 멈춘다(작업의 thread는 앱과 함께 끝난다. 코드가 그렇게 한다. 해 보지 않았다). 지금 있는 페이지(홈)에는 버튼이 없다.

## 안전 규칙

로그인이 없는 화면이 AWS를 바꿀 수 있으므로, 앱은 이것들을 모든 요청에 지킨다(`safety.py`). 거부된 요청은 경로에 닿지 않는다. AWS를 부르지 않고 작업을 시작하지 않는다.

- 이 PC의 주소로만 연다. 앱은 `127.0.0.1`에서만 듣는다. 요청의 `Host`가 `127.0.0.1:<포트>`나 `localhost:<포트>`가 아니면 403이다. 다른 사이트가 자기 이름을 `127.0.0.1`로 돌려 놓고(DNS rebinding) 브라우저로 부르면 그 이름이 `Host`에 실리므로 거부된다.
- 바꾸는 요청(GET과 HEAD가 아닌 것)은 이 화면의 페이지에서 온 것만 받는다. `Origin`이 `http://127.0.0.1:<포트>`나 `http://localhost:<포트>`이어야 하고(`Origin`이 없으면 거부), HTML 폼의 숨은 칸 `token`에 페이지 토큰이 있어야 한다. 토큰은 앱을 띄울 때마다 새로 만들고, 이 화면의 페이지에만 들어 있다(상수 시간으로 비교한다). 앱을 다시 띄운 뒤 예전 탭에서 누르면 403이고, 페이지를 다시 열면 된다.
- 다른 사이트가 이 화면을 자기 페이지 안의 틀(frame)에 넣지 못한다(`X-Frame-Options: DENY`, `Content-Security-Policy`의 `frame-ancestors 'none'`). 틀에 넣은 화면 위에서 누르게 하는 속임수를 막는다. 같은 정책이 페이지의 스크립트로는 이 앱이 쓴 두 스크립트만 돌게 한다. 둘에는 앱을 띄울 때마다 새로 만드는 nonce가 붙어 있어서, 값에 섞여 들어온 마크업이 이스케이프를 지나더라도 스크립트로는 돌지 않는다. 이 앱 밖의 스크립트, 스타일, 그림도 가져오지 못하게 한다.
- 계정 ID는 화면을 떠나지 않는다. 앱이 보내는 모든 HTML과 JSON 본문을 `aws_helpers.mask`에 통과시켜 12자리 계정 ID를 `<ACCOUNT>`로 바꾼다. 허브의 값을 읽기 전(계정을 아직 모를 때)에는 12자리 숫자를 모두 바꾼다.
- 개발자나 에이전트가 정한 글(레코드의 설명, 팀, 프레임워크, 시험 호출의 답, 오류)은 템플릿 엔진이 이스케이프한다. 템플릿의 파일 이름과 상관없이 모든 템플릿이 이스케이프한다. 이스케이프하지 않는 것은 이 리포가 쓴 마크업(메뉴의 아이콘)뿐이다.

이 규칙이 막지 못하는 것:

- 다른 사이트의 페이지가 브라우저에게 이 화면의 페이지를 GET하게 하는 것(링크, 그림 주소). `Host`는 `127.0.0.1:<포트>`라서 받으므로, 그 페이지의 AWS 읽기가 띄운 셸의 자격 증명으로 돈다. 바꾸는 요청은 아니고, 그 사이트는 답을 읽지 못한다(브라우저는 다른 출처의 답을 그 사이트의 스크립트에 넘기지 않는다).
- 이 PC에서 도는 프로그램과 이 PC의 다른 사용자. 그들은 `127.0.0.1:<포트>`를 부를 수 있고, 페이지(GET은 토큰이 필요 없다)에서 토큰을 읽어 버튼을 누를 수 있다. 여럿이 쓰는 PC에서는 띄우지 않는다.
- 브라우저 확장 프로그램처럼 이 화면의 페이지 안에서 도는 코드.
- 앱 앞에 프록시를 두거나 포트를 밖으로 여는 것. 앱은 그런 쓰임을 생각하지 않았다.
- 자격 증명의 범위. 화면은 띄운 셸의 자격 증명이 허락하는 만큼 할 수 있다.
- 통신은 HTTP다. 이 PC 안의 통신(loopback)이라 암호화하지 않는다.

## 시험과 확인

동작은 단위 시험이 정한다(`tests/test_hub_ui_app.py`, `tests/test_hub_ui_jobs.py`, `tests/test_hub_ui_home.py`). 시험은 `tests/fakes.py`의 가짜 AWS 클라이언트로 돌고 AWS를 부르지 않는다. 2026-11-23에 허브가 올라와 있지 않은 계정(`us-west-2`, 접두어 `hub`)에서 `python -m platform_team.hub_ui`로 띄워 봤다. 첫 페이지가 200으로 "이 계정과 리전에 허브가 배포되어 있지 않습니다"와 읽은 곳(`/hub/platform/`)을 보였고, `Host: evil.example:8300`인 요청은 403이었다. 올라와 있는 허브에서는 아직 띄워 보지 않았다.

화면의 틀(색, 밝은 테마와 어두운 테마, 메뉴, 단계 띠, 폼 스크립트), 글 표, 시각 형식은 [ai-governance-hub](https://github.com/gonsoomoon-ml/ai-governance-hub)(MIT-0)에서 가져와 고쳤다. 리포 루트의 `NOTICE`에 적었다.
